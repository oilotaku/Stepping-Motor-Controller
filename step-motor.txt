3. 底層通訊與硬體避坑細節（開發核心）這兩台儀器都屬於經典但年代較久的硬體，在 Python 聯動時必須嚴格遵守以下物理與通訊限制，否則極易造成硬體當機或量測數據失真：A. 駿河精機 DS112 控制細節指令與結束符：採用 ASCII 碼控制。每條指令發送時，尾端必須強制加上 \r\n (CR+LF)，控制器才會辨識。通訊參數：鮑率預設通常為 9600，8 位資料位，1 位停止位，無校驗。運動同步機制：發送移動指令（如 1M+1000 再發 1G）後，Python 不可立即讀取光功率。必須透過 !: 指令進行輪詢（Polling），確認狀態從 B (Busy) 變為 R (Ready) 後，代表滑台已完全停穩。B. HP 8153A 控制細節指令與結束符：採用標準 SCPI 指令（指令結構包含 Slot，如 :SENS1:POW...）。寫入與讀取時，尾端必須強制加上 \n (LF)。內建處理器延遲：HP 8153A 內部微處理器較慢。在 Python 迴圈中連續寫入指令或查詢功率時，每次通訊之間強烈建議加上 time.sleep(0.03) ~ 0.05 秒的延遲，以防 GPIB 緩衝區溢位導致「Query INTERRUPTED」錯誤。取樣時間（Averaging Time）：進行快速滑台掃描時，建議將硬體取樣時間調短（如 :SENS1:POW:ATIM 100MS），以加速整體自動化流程。C. 機構震動與線路干擾馬達動，則不讀光：步進馬達移動時會產生微小物理震動，會即時影響光纎的耦合效率（Coupling Efficiency）。標準流程為：馬達移動 → 輪詢確認停止 → 額外延遲 30ms 等待震動衰減 → 讀取 HP 8153A 功率值。單執行緒（Single-Thread）限制：避免使用 Python 多執行緒同時對 GPIB 與串口發送通訊，全程應使用單一量測主執行緒（如 PyMeasure 的 Procedure.execute）依序執行。4.
